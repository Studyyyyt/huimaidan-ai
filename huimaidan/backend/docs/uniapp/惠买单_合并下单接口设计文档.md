# 惠买单合并下单接口设计文档

更新时间：2026-06-12

## 1. 需求背景

当前下单支付页面有两个标签："优惠价格"和"不参与会员折扣"，需要合并为一个页面，同时显示两个输入框：
- **优惠金额**：支持会员折扣、优惠券、积分
- **不参与优惠金额**：不使用任何优惠（会员折扣、优惠券、积分都不使用）

最终支付金额 = 优惠金额 + 不参与优惠金额

## 2. 接口设计

### 2.1 合并下单接口

**接口地址**：`POST /api/huimaidan/order/createCombined`

**功能**：创建订单并支付，支持优惠金额和不参与优惠金额的分离计算

### 2.2 请求参数

```typescript
export interface IOrderCreateCombinedParams {
  /** 商户ID */
  mer_id: number

  /** 优惠金额（支持会员折扣、优惠券、积分） */
  discount_amount: string

  /** 不参与优惠金额（不使用任何优惠） */
  no_discount_amount: string

  /** 支付方式 */
  pay_type: string

  // 以下参数只对优惠金额生效

  /** 优惠券ID（可选，只针对优惠金额） */
  couponId?: number

  /** 是否使用积分（可选，只针对优惠金额） */
  usePoints?: boolean

  /** 是否使用会员折扣（可选，默认true，只针对优惠金额） */
  useMemberDiscount?: boolean

  /** 备注（可选） */
  mark?: string
}
```

### 2.3 请求示例

```json
{
  "mer_id": 123,
  "discount_amount": "80.00",
  "no_discount_amount": "20.00",
  "pay_type": "routine",
  "couponId": 456,
  "usePoints": true,
  "useMemberDiscount": true,
  "mark": "请安排靠窗位置"
}
```

### 2.4 响应结果

```typescript
export interface IOrderCreateCombinedResult {
  /** 订单ID */
  order_id: number

  /** 订单号 */
  order_no?: string

  /** 支付金额（实际需要支付的金额） */
  pay_price: string

  /** 优惠信息快照 */
  discount?: {
    /** 优惠类型 */
    discount_type: string
    /** 优惠名称 */
    title: string
    /** 优惠金额 */
    saved_amount: string
    /** 会员折扣金额 */
    member_discount_amount?: string
    /** 优惠券抵扣金额 */
    coupon_discount_amount?: string
    /** 积分抵扣金额 */
    points_discount_amount?: string
  }
}
```

## 3. 后端处理逻辑

### 3.1 优惠金额部分

1. **会员折扣**：如果 `useMemberDiscount=true`，计算会员折扣
2. **优惠券抵扣**：如果提供了 `couponId`，验证并使用优惠券
3. **积分抵扣**：如果 `usePoints=true`，计算积分抵扣

### 3.2 不参与优惠金额部分

1. 不计算会员折扣
2. 不使用优惠券
3. 不使用积分
4. 直接计入最终支付金额

### 3.3 最终支付金额计算

```
最终支付金额 = 优惠金额 - 会员折扣 - 优惠券抵扣 - 积分抵扣 + 不参与优惠金额
```

## 4. 错误处理

| 错误码 | 错误信息 | 说明 |
|--------|----------|------|
| 400 | 参数错误 | 缺少必填参数或参数格式错误 |
| 400 | 金额无效 | discount_amount 和 no_discount_amount 不能同时为空或<=0 |
| 400 | 优惠券不可用 | 优惠券不适用当前商户或金额不足 |
| 400 | 积分不足 | 用户积分不足以抵扣 |
| 400 | 请先配置惠买单优惠叠加策略 | 后台未配置优惠叠加策略 |
| 500 | 服务器错误 | 服务器内部错误 |

## 5. 与现有接口的关系

| 接口 | 功能 | 使用场景 |
|------|------|----------|
| `/api/huimaidan/order/prepare` | 创建待支付订单（不支持优惠） | 旧接口，可废弃 |
| `/api/huimaidan/order/create` | 创建订单并支付（支持优惠） | 旧接口，可废弃 |
| `/api/huimaidan/order/createCombined` | 合并下单（支持优惠金额+不参与优惠金额） | 新接口，推荐使用 |

## 7. 注意事项

1. **优惠券范围**：优惠券只针对"优惠金额"部分使用
2. **积分范围**：积分只针对"优惠金额"部分使用
3. **会员折扣范围**：会员折扣只针对"优惠金额"部分使用
4. **金额校验**：`discount_amount` 和 `no_discount_amount` 至少有一个大于0
5. **兼容性**：新接口应保留与旧接口相同的错误处理逻辑

- discount_amount: "80"

- 预期：优惠金额80元计算折扣，不参与优惠金额20元不计算折扣

- discount_amount: "100"

- 预期：优惠券和积分都只针对100元优惠金额计算
