# 惠买单微信小程序登录对接文档

更新时间：2026-06-11

## 一、文档目的

本文档基于项目当前已实现的微信小程序登录相关接口整理，供前端直接对接使用。

本文档只整理以下登录相关能力：

- 小程序登录前判定。
- 小程序登录获取 token。
- 小程序手机号绑定登录。
- 登录后用户信息获取。
- 小程序 token 无感续期。
- 退出登录。

## 二、接口基准

- Base URL：`/api`
- 认证方式：`Authorization: Bearer {token}`
- 返回格式说明：

当前项目登录相关接口存在两种实际响应结构，前端不能假设所有接口都长成同一层级。

### 2.1 `success()` 返回结构

适用于：

- `/api/auth/mp_login_type`
- `/api/auth/mp`
- `/api/auth/mp_phone`
- `/api/auth/refresh_token`
- `/api/user`
- `/api/logout`

示例：

```json
{
  "status": 200,
  "message": "success",
  "data": {}
}
```

### 2.2 `status()` 返回结构

适用于：

- `/api/auth`

示例：

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "status": 200,
    "result": {}
  }
}
```

说明：

- 当前这组接口实际使用的是 `status / message / data`
- 登录流程中存在外层 `status = 200`，但内层 `data.status = 201` 的中间态，表示“需要继续绑定手机号”
- 前端不能直接写 `res.data.token`，必须先判断当前接口的返回层级

## 三、实际可用接口清单

| 用途 | 方法 | 路径 | 是否登录 |
| --- | --- | --- | --- |
| 查询小程序登录方式 | POST | `/auth/mp_login_type` | 否 |
| 小程序授权登录 | POST | `/auth` | 否 |
| 小程序直接授权登录（兼容旧流程） | POST | `/auth/mp` | 否 |
| 小程序手机号绑定登录 | POST | `/auth/mp_phone` | 否 |
| 小程序 token 无感续期 | POST | `/auth/refresh_token` | 是 |
| 获取当前登录用户信息 | GET | `/user` | 是 |
| 退出登录 | POST | `/logout` | 是 |

## 四、推荐对接流程

### 4.1 推荐流程说明

当前项目建议前端优先按以下顺序接入：

1. 小程序调用 `wx.login` 或 `uni.login` 获取 `code`。
2. 调用 `POST /api/auth/mp_login_type` 查询当前是否强制绑定手机号。
3. 根据返回结果决定：
   - 不需要绑定手机号：调用 `POST /api/auth` 完成登录。
   - 需要绑定手机号：先调用 `POST /api/auth` 获取中间态 `key`，再调用 `POST /api/auth/mp_phone` 完成绑定并拿 token。
4. 登录成功后保存 `token`。
5. 调用 `GET /api/user` 获取当前用户信息。
6. 本地 token 过期或接口返回 401 时，携带旧 token 调用 `POST /api/auth/refresh_token` 换取新 token，再重放原请求。

### 4.2 为什么推荐这条流程

原因很直接：

- `POST /api/auth/mp` 在系统开启强制手机号绑定时会直接返回失败：`请绑定手机号`。
- `POST /api/auth` + `POST /api/auth/mp_phone` 这套流程兼容“直接登录”和“先绑手机号再登录”两种场景。
- `POST /api/auth/mp_login_type` 可以让前端提前判断流程，避免用户点了登录后才看到后端失败。

## 五、接口详情

### 5.1 查询小程序登录方式

- 方法：`POST`
- 路径：`/api/auth/mp_login_type`
- 说明：查询当前小程序用户是否需要绑定手机号，以及绑定时要使用的临时 `key`

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | string | 是 | `wx.login` 返回的临时登录凭证 |
| spread | number | 否 | 分销/邀请人 ID，默认 `0` |

#### 响应示例

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "bindPhone": true,
    "key": "Uxxxxxxxx",
    "wechat_phone_switch": "1"
  }
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| bindPhone | boolean | `true` 表示当前登录流程必须先绑定手机号 |
| key | string | 需要绑定手机号时返回的临时授权键 |
| wechat_phone_switch | string/int | 后台配置的手机号快速验证开关，前端原样读取即可 |

#### 前端处理建议

- `bindPhone = false`：直接进入 `5.2 小程序授权登录`
- `bindPhone = true`：进入“授权登录 -> 绑定手机号”的两步流程

### 5.2 小程序授权登录

- 方法：`POST`
- 路径：`/api/auth`
- 说明：推荐使用的统一登录入口，小程序场景传 `auth.type = routine`

#### 请求参数

```json
{
  "auth": {
    "type": "routine",
    "auth": {
      "code": "wx.login 返回的 code",
      "spread": 0,
      "spread_code": ""
    }
  }
}
```

#### 参数说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| auth.type | string | 是 | 固定传 `routine` |
| auth.auth.code | string | 是 | `wx.login` 返回的 code |
| auth.auth.spread | number | 否 | 邀请人 ID |
| auth.auth.spread_code | string/object | 否 | 小程序码携带的推广参数，没有可不传 |

#### 登录成功响应示例

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "status": 200,
    "result": {
      "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
      "exp": 31536000,
      "expires_time": 1781059200,
      "user": {
        "uid": 10001,
        "account": "13800000000",
        "phone": "13800000000",
        "nickname": "微信用户",
        "avatar": "",
        "user_type": "routine"
      }
    }
  }
}
```

#### 需要绑定手机号时的中间态响应

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "status": 201,
    "result": {
      "key": "Uxxxxxxxx",
      "wechat_phone_switch": "1"
    }
  }
}
```

#### 前端处理规则

- 外层 `status !== 200`：请求失败
- 外层 `status === 200` 且 `data.status === 200`：登录成功，读取 `data.result.token`
- 外层 `status === 200` 且 `data.status === 201`：说明用户还未绑定手机号，进入 `5.4 小程序手机号绑定登录`
- 其他状态：按失败处理并展示后端 `message`

### 5.3 小程序直接授权登录（兼容旧流程）

- 方法：`POST`
- 路径：`/api/auth/mp`
- 说明：兼容旧版小程序授权登录流程，不建议新前端优先使用

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | string | 是 | `wx.login` 返回的 code |
| iv | string | 否 | 微信用户信息解密 iv |
| encryptedData | string | 否 | 微信用户信息加密数据 |
| spread_spid | number | 否 | 邀请人 ID |
| spread_code | string/object | 否 | 小程序码推广参数 |

#### 成功响应

成功结构与 `5.2 小程序授权登录` 一致：

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "token": "xxx",
    "exp": 31536000,
    "expires_time": 1781059200,
    "user": {}
  }
}
```

#### 使用限制

- 当后台开启强制手机号绑定时，该接口会直接返回：`请绑定手机号`
- 因此新前端不要把它作为唯一登录入口

### 5.4 小程序手机号绑定登录

- 方法：`POST`
- 路径：`/api/auth/mp_phone`
- 说明：在 `5.2` 返回需要绑定手机号后，用于完成手机号绑定并最终拿到 token

#### 新版主协议：手机号快速验证组件

前端使用微信手机号快速验证组件时，推荐按以下字段提交：

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| auth_token | string | 是 | 来自 `5.1` 或 `5.2` 返回的 `key` |
| phone_code | string | 是 | 微信手机号快速验证组件回调 `detail.code` |

#### 请求示例

```json
{
  "auth_token": "Uxxxxxxxx",
  "phone_code": "getPhoneNumber 回调 detail.code"
}
```

#### 字段说明

- `phone_code` 是手机号快速验证组件返回的动态令牌
- 这个 `phone_code` 不是 `wx.login()` 返回的登录 `code`
- 新版主流程下，不需要额外再传 `wx.login()` 的登录 `code`

#### 兼容旧协议

为了兼容旧版前端，后端仍保留以下旧参数组合：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | string | `wx.login()` 返回的登录 code |
| iv | string | 微信加密数据 iv |
| encryptedData | string | 微信加密手机号数据 |

旧协议只用于兼容，不建议新前端继续使用。

#### 成功响应

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "token": "xxx",
    "exp": 31536000,
    "expires_time": 1781059200,
    "user": {
      "uid": 10001,
      "account": "13800000000",
      "phone": "13800000000",
      "nickname": "微信用户"
    }
  }
}
```

#### 失败场景

| 提示 | 含义 |
| --- | --- |
| `操作超时` | `auth_token` 已失效或未传 |
| `授权失败,参数有误` | 旧协议缺少登录 `code` |
| `请获取手机号授权 code` | 新协议缺少 `phone_code` |
| `获取手机号失败` / 微信返回的 `errmsg` | 手机号快速验证组件 code 无效或已过期 |
| `获取session_key失败，请检查您的配置！` | 小程序配置异常 |

### 5.5 获取当前登录用户信息

- 方法：`GET`
- 路径：`/api/user`
- 说明：登录成功后用于刷新当前用户登录态和基础资料

#### 请求头

```http
Authorization: Bearer {token}
```

#### 成功响应示例

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "uid": 10001,
    "account": "13800000000",
    "phone": "13800000000",
    "nickname": "微信用户",
    "avatar": "",
    "pay_price": "0.00",
    "is_promoter": 0,
    "promoter": {},
    "sign_status": false
  }
}
```

说明：

- 该接口返回字段很多，前端只取当前页面需要的字段即可
- 不要自行假定字段精简版结构，以实际返回为准

### 5.6 小程序 token 无感续期

- 方法：`POST`
- 路径：`/api/auth/refresh_token`
- 说明：本地单 token 到期或登录态接口返回 401 时，前端携带旧 token 换取新 token。该接口复用后端 `UserTokenMiddleware`，只有缓存登录态仍在有效期内、用户状态正常时才会续期。

#### 请求头

```http
Authorization: Bearer {token}
```

#### 成功响应

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "token": "xxx",
    "exp": 31536000,
    "expires_time": 1813161600,
    "user": {}
  }
}
```

#### 前端处理规则

- 刷新成功：覆盖本地 `token`、`expires_time`，并重放原请求。
- 刷新失败：清理本地登录态，跳转登录页，提示用户重新登录。
- 刷新成功不弹 toast，保持无感。

### 5.7 退出登录

- 方法：`POST`
- 路径：`/api/logout`
- 说明：清除当前 token

#### 请求头

```http
Authorization: Bearer {token}
```

#### 成功响应

```json
{
  "status": 200,
  "message": "退出登录"
}
```

## 六、前端对接流程图

### 6.1 推荐流程

```text
uni.login()
  -> POST /api/auth/mp_login_type
    -> bindPhone = false
       -> POST /api/auth
       -> 保存 token
       -> GET /api/user

    -> bindPhone = true
       -> POST /api/auth
          -> data.status = 201, 返回 key
       -> 调起微信手机号授权
       -> POST /api/auth/mp_phone
       -> 保存 token
       -> GET /api/user
```

### 6.2 最简兼容流程

```text
uni.login()
  -> POST /api/auth/mp
  -> 保存 token
  -> GET /api/user
```

说明：

- 这个兼容流程只适用于“不强制手机号绑定”的场景
- 新前端不要默认走这条流程

## 七、前端接入约定

### 7.1 token 存储

建议前端统一存储：

- `token`
- `expires_time`
- `user`

### 7.2 成功码判断

前端统一按以下逻辑处理：

- 对 `/api/auth/mp_login_type`、`/api/auth/mp`、`/api/auth/mp_phone`、`/api/auth/refresh_token`、`/api/user`、`/api/logout`
  - `status === 200`：成功
  - 其他：失败
- 对 `/api/auth`
  - `status === 200 && data.status === 200`：登录成功
  - `status === 200 && data.status === 201`：进入手机号绑定流程
  - 其他：失败

### 7.3 必须注意的点

1. `/api/logout` 实际是 `POST`，不是 `GET`
2. 当前项目使用 `POST /api/auth/refresh_token` 做小程序单 token 无感续期，不使用模板遗留的 `/auth/refreshToken`
3. `/api/auth/mp_phone` 新版主协议使用 `auth_token + phone_code`
4. `/api/auth/mp` 是兼容旧流程，不适合作为新版本唯一登录方案
5. `/api/auth` 的 token 在 `data.result.token`，不是 `data.token`
6. `/api/logout` 成功时只有 `status + message`，不要假设一定有 `data`
7. `phone_code` 是 `getPhoneNumber` 回调返回的动态令牌，不能和 `wx.login()` 的登录 `code` 混用

## 八、建议前端封装

### 8.1 登录判定

```typescript
export interface MpLoginTypeRes {
  bindPhone: boolean
  key: string
  wechat_phone_switch: string | number
}
```

### 8.2 token 结构

```typescript
export interface LoginTokenRes {
  token: string
  exp: number | string
  expires_time: number
  user: Record<string, any>
}

export interface AuthLoginSuccessRes {
  status: 200
  result: LoginTokenRes
}

export interface AuthPhoneBindRes {
  status: 201
  result: {
    key: string
    wechat_phone_switch: string | number
  }
}
```

### 8.3 统一登录分支

```typescript
if (res.status === 200 && res.data?.status === 200) {
  const token = res.data.result.token
}

if (res.status === 200 && res.data?.status === 201) {
  const key = res.data.result.key
  const wechatPhoneSwitch = res.data.result.wechat_phone_switch
}
```

### 8.4 推荐响应解析

```typescript
const isSuccess = (res: any) => res?.status === 200

const getAuthLoginResult = (res: any) => {
  if (res?.status !== 200) return null
  return res?.data?.result ?? null
}

const getCommonResult = (res: any) => {
  if (res?.status !== 200) return null
  return res?.data ?? null
}
```

## 九、当前结论

给前端的最终对接口径建议统一为：

- 新版小程序登录主流程：`/api/auth/mp_login_type` -> `/api/auth` -> 必要时 `/api/auth/mp_phone`
- 登录完成后：`/api/user`
- token 无感续期：`/api/auth/refresh_token`
- 退出登录：`/api/logout`
- 兼容旧流程：`/api/auth/mp`
- 其中只有 `/api/auth` 使用了 `data.status + data.result` 二层结构，其它登录相关接口直接返回 `data`

补充说明：

- `POST /api/auth/mp_login_type` 在强制手机号绑定场景下，正常应返回 `bindPhone=true`
- `POST /api/auth` 在小程序未绑定手机号时，正常应返回 `data.status=201` 的绑定中间态，而不是直接返回 token
- 当前登录链路已按新版手机号快速验证组件协议完成后端支持，前端对接以 `auth_token + phone_code` 为主协议

如果前端只想接一版，不要直接按旧文档里的 `POST /auth/wxLogin -> /api/auth/mp` 单点接入，应该按本文档的推荐流程对接。
