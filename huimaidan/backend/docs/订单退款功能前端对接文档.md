# 订单退款功能前端对接文档

> **文档版本**: v1.0
> **更新日期**: 2026-06-16
> **适用端**: 用户端小程序/APP + 商户端H5/小程序

---

## 一、接口变更概览

### 1.1 变更说明

本次退款功能从**商品粒度**调整为**订单粒度**，用户无需选择具体商品，直接对订单进行全额退款。

### 1.2 接口列表

| 接口 | 方法 | 路径 | 调用端 | 状态 |
|------|------|------|--------|------|
| 用户退款申请 | POST | `/api/store/order/refund/{id}` | 用户端 | ✅ 已变更 |
| 订单可退款信息 | GET | `/api/merchant/store/refundorder/check/{id}` | 商户端 | ✅ 已变更 |
| 商户发起退款 | POST | `/api/merchant/store/refundorder/create` | 商户端 | ✅ 已变更 |
| 退款列表 | GET | `/api/merchant/store/refundorder/lst` | 商户端 | 无变化 |
| 退款详情 | GET | `/api/merchant/store/refundorder/detail/{id}` | 商户端 | 无变化 |
| 退款审核 | POST | `/api/merchant/store/refundorder/status/{id}` | 商户端 | 无变化 |

> **注意**: 商户端退款接口前缀为 `store/refundorder`，不是 `store/order/refund`

## 二、用户端接口

### 2.1 申请退款

#### 接口信息

- **URL**: `POST /api/store/order/refund/{id}`
- **认证**: 需要登录（Bearer Token）
- **说明**: 用户对订单申请全额退款

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | int | 是 | 订单ID（URL参数） |
| refund_message | string | 是 | 退款原因，最大128字符 |
| mark | string | 否 | 备注，最大128字符 |
| pics | array | 否 | 凭证图片URL数组，最多9张 |

#### 请求示例

```json
{
  "refund_message": "不想要了",
  "mark": "",
  "pics": ["https://example.com/img1.jpg"]
}
```

#### 响应示例

**成功响应**:
```json
{
  "code": 200,
  "msg": "提交申请成功",
  "data": {
    "refund_order_id": 12345
  }
}
```

**失败响应**:
```json
{
  "code": 100,
  "msg": "订单已退款",
  "data": []
}
```

#### 错误码说明

| 错误码 | 错误信息 | 说明 |
|--------|----------|------|
| 100 | 订单不存在 | 订单ID无效或不属于当前用户 |
| 100 | 订单已退款 | 订单已处于退款状态 |
| 100 | 订单不支持退款 | 订单状态不支持退款操作 |
| 100 | 订单已过退款期限 | 超过15天退款有效期 |
| 100 | 订单未支付 | 订单尚未完成支付 |
| 100 | 订单已配送，不支持退款 | 同城配送订单已发货 |
| 100 | 退款原因不能为空 | refund_message 未传或为空 |
| 100 | 退款原因超过限制 | refund_message 超过128字符 |

#### 前端代码示例（小程序）

```javascript
// 申请退款
async function submitRefund(orderId, refundMessage, pics = []) {
  try {
    const res = await wx.request({
      url: `${baseUrl}/api/store/order/refund/${orderId}`,
      method: 'POST',
      header: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      data: {
        refund_message: refundMessage,
        pics: pics
      }
    });

    if (res.data.code === 200) {
      wx.showToast({ title: '提交成功' });
      // 跳转到退款详情页
      wx.navigateTo({
        url: `/pages/refund/detail?id=${res.data.data.refund_order_id}`
      });
    } else {
      wx.showToast({ title: res.data.msg, icon: 'none' });
    }
  } catch (error) {
    wx.showToast({ title: '网络错误', icon: 'none' });
  }
}
```

// 审核退款
async function auditRefund(refundOrderId, status, failMessage = '') {
  const data = { status };

  if (status === -1 && !failMessage) {
    ElMessage.warning('请输入拒绝原因');
    return;
  }

  if (status === -1) {
    data.fail_message = failMessage;
  }

  try {
    const res = await axios.post(
      `/api/merchant/store/refundorder/status/${refundOrderId}`,
      data
    );

    if (res.data.code === 200) {
      ElMessage.success('审核成功');
      this.refreshRefundList();
    } else {
      ElMessage.error(res.data.msg);
    }
  } catch (error) {
    ElMessage.error('网络错误');
  }
}

## 五、状态码对照表

### 5.1 退款状态

| 状态码 | 状态名称 | 说明 | 用户端显示 | 商户端操作 |
|--------|----------|------|------------|------------|
| 0 | 待审核 | 退款申请已提交，等待审核 | 待审核 | 可同意/拒绝 |
| -1 | 审核未通过 | 商户拒绝了退款申请 | 退款失败 | - |
| 1 | 待退货 | 退款申请已通过，等待用户退货 | 待退货 | - |
| 2 | 待收货 | 商户已收到退回商品 | 待收货 | 可确认退款 |
| 3 | 已退款 | 退款已完成 | 退款成功 | - |
| 4 | 平台介入 | 用户申请平台介入处理 | 平台处理中 | - |
| -2 | 已取消 | 用户取消了退款申请 | 已取消 | - |

### 5.2 订单状态

| 状态码 | 状态名称 | 说明 | 是否可退款 |
|--------|----------|------|------------|
| 0 | 待核销 | 订单已支付，待核销 | ✅ 是 |
| 1 | 已完成 | 订单已完成 | ❌ 否 |
| -1 | 已取消 | 订单已取消 | ❌ 否 |
| -2 | 已关闭 | 订单已关闭 | ❌ 否 |
| 9 | 待使用 | 订单待使用 | ✅ 是 |
| 10 | 已完成 | 订单已完成 | ❌ 否 |

## 六、注意事项

### 6.1 用户端

1. **退款金额固定**: 退款金额 = 订单实付金额，不可修改
2. **全额退款**: 每次退款都是全额退款，不支持部分退款
3. **退款次数**: 每个订单只能申请一次退款
4. **退款期限**: 订单完成后15天内可申请退款

### 6.2 商户端

1. **自动审核**: 商户可在后台配置自动审核开关
2. **退款原因必填**: 发起退款时必须填写退款原因
3. **退款通知**: 退款操作会触发微信/短信通知

### 6.3 接口调用

1. **认证**: 所有接口需要携带 Authorization Header
2. **幂等性**: 重复提交相同退款申请会返回"订单已退款"错误
3. **并发控制**: 使用事务保证并发安全
