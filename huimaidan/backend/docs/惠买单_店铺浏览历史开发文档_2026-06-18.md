# 惠买单店铺浏览历史开发文档

更新时间：2026-06-18

## 1. 目标

为惠买单小程序增加“店铺浏览历史”能力。用户进入店铺详情页后，后端记录该用户最近浏览过的真实店铺；用户中心可分页查询、删除单条、批量删除或清空浏览历史；前端按返回字段展示店铺卡片。

本需求只记录店铺，不记录首页、店铺列表、买单页、订单页、商品页或其他页面。

## 2. 当前代码调研结论

### 2.1 已有可复用能力

| 能力 | 现有位置 | 复用方式 |
| --- | --- | --- |
| 商户详情入口 | `GET /api/huimaidan/store/detail/:id`，`app/controller/api/huimaidan/Store.php` | 店铺详情加载成功后触发记录。 |
| 商户列表/详情展示字段 | `app/common/repositories/huimaidan/MerchantDiscoveryRepository.php`、`MerchantPresenter.php` | 历史列表返回店铺卡片时复用 `MerchantPresenter::present()` 的展示口径。 |
| 登录态可选详情接口 | `route/api.php` 中详情接口挂 `UserTokenMiddleware::class, false` | 未登录仍可看详情；只有登录用户写浏览历史。 |
| 商品浏览历史去重思路 | `app/common/repositories/user/UserHistoryRepository.php`、`UserHistoryDao::createOrUpdate()` | 复用“同一用户同一资源只保留一条，重复浏览更新 `update_time`”的业务思路。 |
| 用户中心登录接口分组 | `route/api.php` 顶部强制登录分组内 `huimaidan/user/*` | 新增历史列表、删除接口放入该分组，复用强制登录。 |
| 收藏商户列表字段经验 | `UserRelationRepository::search(type=10)` | 可参考商户关联加载方式，但不直接复用收藏表。 |

### 2.2 不建议直接复用的能力

| 现有能力 | 不直接复用原因 |
| --- | --- |
| `eb_user_visit` / `/api/common/visit` | 当前只保存 `type`、`type_id`、`content`，页面浏览以路径字符串记录，不解析商户 ID；列表只能返回商品访问历史或搜索日志，不能稳定返回店铺卡片。 |
| `eb_user_history` | 当前强绑定 SPU 商品历史，`res_type=1` 会关联 `store_spu`；直接塞商户会破坏商品浏览历史语义。 |
| `VisitProductMiddleware` | 只适配商品详情 `id + product_type`，异步队列写 SPU 浏览历史；店铺浏览需要按商户状态校验、按商户去重，不适合复用该中间件。 |

## 3. 推荐方案

采用专表 `eb_user_merchant_history` 存储店铺浏览历史，新增 `huimaidan` 领域 Repository/Dao/Model，店铺详情接口登录用户自动记录，用户中心新增专用查询与删除接口。

理由：

- 查询语义清晰：店铺历史和商品历史、页面 PV、搜索日志分离。
- 前端展示稳定：历史记录可直接关联 `merchant`，复用惠买单店铺展示字段。
- 去重和删除简单：唯一键约束 `uid + mer_id`，重复浏览只更新时间和次数。
- 保持 CRMEB 原厂兼容：不改原 `user_history`、`user_visit` 表语义，不影响商品推荐、统计和后台 PV。

## 4. 数据库设计

新增 SQL 文件：

```text
docs/sql/惠买单_店铺浏览历史表.sql
```

表结构：

```sql
CREATE TABLE IF NOT EXISTS `eb_user_merchant_history` (
  `user_merchant_history_id` int(10) unsigned NOT NULL AUTO_INCREMENT COMMENT '店铺浏览历史ID',
  `uid` int(10) unsigned NOT NULL DEFAULT '0' COMMENT '用户ID',
  `mer_id` int(10) unsigned NOT NULL DEFAULT '0' COMMENT '商户ID',
  `visit_count` int(10) unsigned NOT NULL DEFAULT '1' COMMENT '浏览次数',
  `last_visit_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '最后浏览时间',
  `create_time` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`user_merchant_history_id`) USING BTREE,
  UNIQUE KEY `uniq_uid_mer_id` (`uid`, `mer_id`) USING BTREE,
  KEY `idx_uid_last_visit` (`uid`, `last_visit_time`) USING BTREE,
  KEY `idx_mer_id` (`mer_id`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='用户店铺浏览历史';
```

回滚说明：

```sql
DROP TABLE IF EXISTS `eb_user_merchant_history`;
```

不做历史数据迁移。旧 `eb_user_visit` 中已写入的页面路径无法可靠反推出商户 ID，迁移会引入不确定数据。

### 5.3 记录触发机制

触发入口：

```text
GET /api/huimaidan/store/detail/:id
```

规则：

- 未登录：正常返回店铺详情，不写浏览历史。
- 已登录：店铺详情查询成功后写入浏览历史。
- 商户不存在、未启用、未通过惠买单展示资格：详情接口本身失败，不写历史。
- 同一用户重复浏览同一店铺：不新增多条记录，更新 `last_visit_time`，`visit_count + 1`。
- 每个用户最多保留最近 60 条店铺浏览历史；写入成功后如超过 60 条，自动删除该用户最旧记录。
- 写入失败：接口直接返回失败，不隐藏错误；服务端记录错误日志。不得因为“只是历史记录”静默降级。

说明：不使用中间件做第一版记录。原因是店铺详情当前可匿名访问且详情 Repository 已经包含惠买单可展示商户校验，把写入放在详情成功后更容易保证“只记录真实可访问店铺”。

### 5.4 列表查询逻辑

Repository 查询条件：

- 必须带 `uid`。
- 只返回该用户自己的历史。
- 按 `last_visit_time DESC` 排序。
- 关联商户时只返回 `is_del=0`、`status=1`、`mer_state=1` 的店铺。
- 对已下架或禁用商户：默认不返回，避免前端展示不可访问店铺。

## 6. API 设计

以下接口均要求登录，走现有强制登录分组。

### 6.1 获取店铺浏览历史

```text
GET /api/huimaidan/user/merchant_history
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| page | number | 否 | 默认 1。 |
| limit | number | 否 | 默认使用项目分页默认值。 |
| latitude | string/number | 否 | 用户纬度；与 `longitude` 同传时计算距离。 |
| longitude | string/number | 否 | 用户经度；与 `latitude` 同传时计算距离。 |

响应：

```json
{
  "count": 10,
  "list": [
    {
      "history_id": 12,
      "mer_id": 1001,
      "browseTime": "2026-06-18 14:30:00",
      "visitCount": 3,
      "shop": {}
    }
  ]
}
```

错误：

| 场景 | 错误 |
| --- | --- |
| 经纬度只传一个 | `请同时提供经纬度` |
| 经纬度格式错误 | `经纬度格式错误` |
| 未登录 | 复用现有 Token 中间件错误 |

### 6.2 删除单条店铺浏览历史

```text
POST /api/huimaidan/user/merchant_history/delete/:id
```

路径参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | number | 是 | `history_id`。 |

规则：

- 只能删除当前登录用户自己的记录。
- 记录不存在或不属于当前用户，返回 `浏览记录不存在`。

成功响应：

```json
"浏览记录已删除"
```

### 6.3 批量删除或清空店铺浏览历史

```text
POST /api/huimaidan/user/merchant_history/batch_delete
```

请求：

```json
{
  "history_ids": [12, 13]
}
```

清空全部：

```json
{
  "clear": 1
}
```

规则：

- `history_ids` 和 `clear=1` 必须二选一。
- `history_ids` 只能删除当前登录用户自己的记录；若任一 ID 越权或不存在，直接失败。
- `clear=1` 只清空当前登录用户的店铺浏览历史。
- 系统自动保留最近 60 条记录，超过后删除最旧记录；前端无需处理截断逻辑。

成功响应：

```json
"浏览记录已删除"
```

## 7. 前端小程序对接说明

### 7.1 店铺详情页

前端无需额外调用写入接口。详情页保持调用：

```ts
request.get(`/huimaidan/store/detail/${merId}`)
```

登录用户浏览成功后由后端自动记录。未登录用户浏览不记录，登录后再次进入详情才记录。

### 7.2 浏览历史页

新增 API 封装：

```ts
export const shopHistoryApi = {
  list: (params: { page?: number; limit?: number; latitude?: number; longitude?: number }) =>
    request.get('/huimaidan/user/merchant_history', params),
  delete: (historyId: number) =>
    request.post(`/huimaidan/user/merchant_history/delete/${historyId}`),
  batchDelete: (historyIds: number[]) =>
    request.post('/huimaidan/user/merchant_history/batch_delete', { history_ids: historyIds }),
  clear: () =>
    request.post('/huimaidan/user/merchant_history/batch_delete', { clear: 1 }),
}
```

页面展示建议：

- 使用 `item.shop` 渲染店铺卡片。
- 点击卡片跳转到 `/pages/store/detail/index?id=${item.mer_id}`，具体路径以前端真实页面为准。
- 删除时传 `history_id`，不要传 `mer_id`。
- 空列表展示“暂无浏览记录”。
- 接口失败时直接展示后端错误信息，不使用假数据填充。

### 7.3 与旧接口的边界

| 接口 | 用途 |
| --- | --- |
| `GET /api/user/history` | CRMEB 商品/SPU浏览历史，不用于惠买单店铺历史。 |
| `POST /api/common/visit` | 页面 PV 或小程序页面访问记录，不用于店铺历史列表。 |
| `GET /api/huimaidan/user/merchant_history` | 惠买单店铺浏览历史，本需求新增。 |

## 8. 测试计划

新增测试文件：

```text
tests/huimaidan/UserMerchantHistoryRepositoryTest.php
tests/huimaidan/UserMerchantHistoryControllerGuardTest.php
```

测试点：

- 同一用户首次浏览店铺会创建一条历史。
- 同一用户重复浏览同一店铺只更新同一条历史，`visit_count + 1`。
- 不同用户浏览同一店铺互不影响。
- 未登录访问店铺详情不写历史。
- 历史列表只返回当前用户记录。
- 历史列表按 `last_visit_time DESC` 排序。
- 禁用、删除或未启用商户不出现在历史列表。
- 删除单条必须校验 `uid` 归属。
- 批量删除遇到越权 ID 直接失败，不部分删除。
- `clear=1` 只清空当前用户历史。

## 9. 部署与运维

- 需要执行新增 SQL：`docs/sql/惠买单_店铺浏览历史表.sql`。
- 修改 `route/api.php` 后，如生产环境启用路由缓存，需要清理路由缓存。
- 不涉及 Swoole 长驻进程代码；若生产服务使用 Swoole/常驻进程，部署 PHP 代码后仍建议按现有发布流程重启服务。
- 不涉及后台菜单权限。
- 不涉及前端构建，除非小程序端新增浏览历史页面或 API 封装后需要重新发布。

## 10. 已确认决策

1. 已确认：采用专表 `eb_user_merchant_history`，不复用 `eb_user_visit` 或 `eb_user_history`。
2. 已确认：店铺详情接口写历史失败时，按 Debug-First 直接让详情接口失败，不静默跳过。
3. 已确认：历史列表中已禁用、已删除或未通过惠买单展示资格的商户不返回。
4. 已确认：每个用户最多保留最近 60 条店铺历史，超过后自动删除最旧记录。
5. 已确认：本次不在商户后台或平台后台增加“店铺被浏览用户/浏览次数”统计，只做小程序用户侧浏览历史。
