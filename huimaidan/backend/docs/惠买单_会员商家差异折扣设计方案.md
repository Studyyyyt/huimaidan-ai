# 惠买单会员商家差异折扣设计方案

更新时间：2026-06-04

## 一、设计目的

本文档用于修正并确认惠买单会员折扣业务口径。确认后再进入后端开发，不在本文档阶段修改业务代码。

本期会员使用 CRMEB 系统自带的“用户等级”能力，即后台用户等级下的“等级配置、等级管理”。不使用 CRMEB 付费会员功能，不使用 `is_svip`、付费会员购买、付费会员有效期或付费会员权益逻辑。

## 二、核心业务口径

### 2.1 角色和配置权限

- 只有平台 admin 可以配置惠买单商家折扣和会员消费折扣。
- 商户后台不允许新增、编辑、启停或删除惠买单折扣规则。
- 商户后台只保留查看经营数据、订单、结算、垫资池和流水能力。
- 用户端只读取当前登录用户等级对应的真实折扣，不允许前端传入会员等级或折扣。

### 2.2 折扣定义

每个商家存在两类折扣：

| 折扣 | 含义 | 示例 |
| --- | --- | --- |
| 商家结算折扣 | 平台和商家谈定的底价折扣，决定商家最终拿到的钱 | 商家 6 折 |
| 会员消费折扣 | 平台给某个会员等级展示和使用的消费折扣，决定用户实付金额 | 会员 8 折 |

示例：用户消费 100 元，商家结算折扣为 6 折，当前会员消费折扣为 8 折。

- 用户实付：`100 * 0.80 = 80.00`
- 商家应得：`100 * 0.60 = 60.00`
- 平台差价：`80.00 - 60.00 = 20.00`
- 垫资池扣减：`60.00`

平台差价允许为负数，不隐藏、不归零。若会员消费折扣低于商家结算折扣，例如用户 5 折、商家 6 折，则平台差价为 `-10.00`。

### 2.3 会员等级来源

会员等级读取 CRMEB 用户等级字段和等级配置：

- 用户当前等级：优先使用用户表中的 `member_level`。
- 等级定义：使用现有 `user_brokerage` 中 `type=1` 的用户等级配置。
- 等级名称、图标、升级规则等继续复用原有用户等级能力。

不得使用以下能力作为本业务会员判断依据：

- `is_svip`
- 付费会员购买记录
- 付费会员有效期
- 付费会员权益加成

## 三、推荐设计方案

### 3.1 方案选择

推荐采用“商家折扣主表 + 商家会员等级折扣明细表”的设计。

备选方案一：继续复用现有 `eb_huimaidan_discount_rule`，在同表追加会员等级字段。

- 优点：改动小。
- 缺点：同一商家多个会员等级会形成多条规则，和现有折扣、立减、积分抵扣混杂，后续统计和列表展示容易混乱。

备选方案二：新增独立“商家会员折扣矩阵”表。

- 优点：业务语义清晰，天然支持“同商家不同会员等级不同折扣”，不会混淆付费会员和普通优惠规则。
- 缺点：需要新增 SQL、admin 接口和计算逻辑。

推荐方案二。该方案更符合当前需求，也更利于后续扩展不同城市、不同活动期或不同会员等级的商家折扣。

## 四、数据模型设计

### 4.1 商家惠买单折扣配置表

建议新增 `eb_huimaidan_merchant_discount`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `discount_id` | int unsigned | 主键 |
| `mer_id` | int unsigned | 商户 ID |
| `pool_id` | int unsigned | 绑定垫资池 ID |
| `merchant_discount` | decimal(5,2) | 商家结算折扣，如 `0.60` |
| `status` | tinyint | 状态：0 停用，1 启用 |
| `start_time` | datetime null | 生效开始时间 |
| `end_time` | datetime null | 生效结束时间 |
| `sort` | int | 排序 |
| `remark` | varchar(255) | 后台备注 |
| `create_time` | datetime | 创建时间 |
| `update_time` | datetime | 更新时间 |

约束：

- 同一商家同一时间只允许一条启用的主配置。
- 启用配置必须绑定当前商家已启用垫资池。
- `merchant_discount` 必须大于 0 且小于等于 1。

### 4.2 商家会员等级消费折扣表

建议新增 `eb_huimaidan_member_discount`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `member_discount_id` | int unsigned | 主键 |
| `discount_id` | int unsigned | 商家折扣配置 ID |
| `mer_id` | int unsigned | 商户 ID，冗余便于查询 |
| `member_level` | int | 用户等级值，对应 `user.member_level` / `user_brokerage.brokerage_level` |
| `member_discount` | decimal(5,2) | 当前等级用户消费折扣，如 `0.80` |
| `status` | tinyint | 状态：0 停用，1 启用 |
| `create_time` | datetime | 创建时间 |
| `update_time` | datetime | 更新时间 |

约束：

- 同一 `discount_id + member_level` 只允许一条记录。
- `member_discount` 必须大于 0 且小于等于 1。
- `member_level` 必须存在于 `user_brokerage.type=1` 的等级配置中。
- admin 保存或启用商家折扣配置时，必须为所有启用的用户等级配置会员消费折扣。
- 不要求 `member_discount >= merchant_discount`，因为平台可能做补贴，负差价必须真实记录。

### 4.3 订单快照字段

现有 `eb_store_order` 已有惠买单字段：

- `merchant_cost_amount`
- `platform_profit`
- `discount_snapshot`
- `pool_id`
- `pool_transaction_id`
- `order_scene`

建议在 `discount_snapshot` 中补充：

| 字段 | 说明 |
| --- | --- |
| `member_level` | 下单时用户等级 |
| `member_level_name` | 下单时等级名称 |
| `member_discount` | 下单时会员消费折扣 |
| `merchant_discount` | 下单时商家结算折扣 |
| `discount_config_id` | 商家折扣配置 ID |
| `member_discount_id` | 会员等级折扣明细 ID |

历史订单永远按快照展示和统计，不根据后续等级或折扣配置重算。

## 五、计算逻辑

### 5.1 优惠试算

输入：

- 当前登录用户 ID。
- 商户 ID。
- 消费金额。

处理：

1. 查询商户是否正常、未删除、营业中。
2. 查询商户当前启用的惠买单折扣主配置。
3. 校验主配置绑定的垫资池处于启用状态；余额允许不足，不因负数或余额小于本次结算金额而拦截。
4. 获取用户当前 `member_level`。
5. 查询该商户、该会员等级启用的消费折扣。
6. 计算：
   - `pay_amount = original_amount * member_discount`
   - `merchant_cost_amount = original_amount * merchant_discount`
   - `saved_amount = original_amount - pay_amount`
   - `platform_profit = pay_amount - merchant_cost_amount`
7. 返回用户可见字段，不返回商家底价和平台差价。

若当前会员等级没有配置该商家的消费折扣，应显式返回“当前会员等级暂无该商家优惠”，不使用默认折扣、不 mock、不静默降级。

### 5.2 创建订单

创建订单时重新执行试算，不信任前端传入的折扣和金额。

订单落库保存：

- 用户实付金额。
- 商家结算金额。
- 平台差价。
- 垫资池 ID。
- 会员等级和折扣快照。
- 商家结算折扣快照。

### 5.3 支付成功

支付成功后：

1. 校验订单金额和支付回调金额。
2. 按订单快照中的商家结算金额扣减垫资池，允许扣减后余额为负数。
3. 写入垫资池流水。
4. 写入订单支付状态。
5. 同步现有用户等级成长值和推广等级统计。

重复支付回调只返回已支付订单，不重复扣减垫资池，不重复累计会员/推广统计。

## 六、接口设计

### 6.1 平台后台接口

新增或调整平台后台接口，均走 admin Token、权限和日志中间件。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/huimaidan/discount/lst` | 商家折扣配置列表 |
| GET | `/huimaidan/discount/detail/:id` | 商家折扣配置详情 |
| POST | `/huimaidan/discount/create` | 新增商家折扣配置 |
| POST | `/huimaidan/discount/update/:id` | 编辑商家折扣配置 |
| POST | `/huimaidan/discount/status/:id` | 启停商家折扣配置 |
| DELETE | `/huimaidan/discount/delete/:id` | 删除商家折扣配置 |
| GET | `/huimaidan/discount/member_levels` | 获取可配置用户等级列表 |

`create/update` 请求核心字段：

```json
{
  "mer_id": 12,
  "pool_id": 5,
  "merchant_discount": "0.60",
  "status": 1,
  "start_time": "2026-06-01 00:00:00",
  "end_time": null,
  "member_discounts": [
    {
      "member_level": 1,
      "member_discount": "0.90",
      "status": 1
    },
    {
      "member_level": 2,
      "member_discount": "0.80",
      "status": 1
    }
  ]
}
```

### 6.2 商户后台接口

商户后台不提供折扣写接口。

现有商户端折扣写接口建议处理为：

- 后端直接返回业务错误：“惠买单折扣由平台统一配置”。
- 或从商户权限菜单移除对应入口。

为兼容后续商户查看，可保留只读接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/huimaidan/discount/lst` | 当前商户折扣配置只读列表 |
| GET | `/huimaidan/discount/detail/:id` | 当前商户折扣配置只读详情 |

商户只能查看本商户数据。

### 6.3 用户端接口

一期接口路径可保持，但计算逻辑调整为会员等级折扣：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/huimaidan/discount/calculate` | 按当前用户等级试算 |
| POST | `/api/huimaidan/order/create` | 按当前用户等级创建订单 |
| GET | `/api/huimaidan/store/list` | 列表展示当前用户等级可用折扣标签 |
| GET | `/api/huimaidan/store/detail/:id` | 详情展示当前用户等级可用折扣 |

公共商户列表若未登录：

- 展示“登录后查看会员优惠”。
- 不展示折扣区间，不伪造当前用户折扣。
- 列表接口按可选登录处理：登录时返回当前等级折扣，未登录时返回明确未登录状态和登录提示。

## 七、前端展示口径

用户端展示：

- 展示当前会员等级名称。
- 展示该商家对当前等级的消费折扣，如“会员 8 折”。
- 展示优惠金额、实付金额。
- 不展示商家结算折扣。
- 不展示平台差价。
- 不展示垫资池信息。

平台后台展示：

- 商户名称。
- 商家结算折扣。
- 各会员等级消费折扣。
- 平台预估差价。
- 配置状态。
- 生效时间。
- 操作人和更新时间。

商户后台展示：

- 可展示平台为本商户配置的会员消费折扣。
- 可展示商家结算折扣和订单结算金额。
- 不允许商户自行调整折扣。

## 八、与现有实现的冲突和调整点

当前实现中：

- `eb_huimaidan_discount_rule.platform_discount` 表示用户实付折扣。
- `eb_huimaidan_discount_rule.merchant_cost` 表示商家底价折扣。
- 商户后台存在新增、编辑、启停和删除折扣规则接口。

需要调整为：

1. 折扣写权限从商户端迁移到平台 admin。
2. 用户实付折扣不再是商家维度单一字段，而是商家 + 会员等级维度。
3. 试算和下单必须读取当前用户 `member_level`。
4. 用户端返回字段中的 `discount_rate` 改为当前会员等级消费折扣。
5. 商户列表和详情展示当前用户等级对应的会员折扣。
6. 原有折扣、立减、积分抵扣三类规则应暂停用于惠买单会员折扣主流程，避免和会员等级折扣混算。

## 九、SQL 变更预估

本设计需要新增 SQL。

新增表：

- `eb_huimaidan_merchant_discount`
- `eb_huimaidan_member_discount`

可选迁移：

- 不迁移现有商户端折扣配置数据。
- 保留旧表历史数据，不再作为会员商家差异折扣主流程的数据来源。
- 新折扣由 admin 按商家和用户等级重新配置。

不修改：

- CRMEB 付费会员表和字段。
- `is_svip` 逻辑。
- 用户等级原有表结构。
- 原厂支付授权和鉴权逻辑。

## 十、验收标准

1. admin 可以为每个商家配置商家结算折扣。
2. admin 可以为同一商家的不同用户等级配置不同消费折扣。
3. 商户不能新增、编辑、启停或删除折扣配置。
4. 用户 A 和用户 B 若会员等级不同，在同一商家试算得到不同实付金额。
5. 同一用户在不同商家可享受不同消费折扣。
6. 商家结算金额按商家结算折扣计算。
7. 平台差价按用户实付减商家结算金额计算，允许为负数。
8. 订单快照保存下单时会员等级、会员折扣和商家结算折扣。
9. 历史订单不随会员等级和后台折扣配置变更而重算。
10. 垫资池余额允许为负数，只校验池子绑定关系和启用状态。
10. 未配置当前会员等级折扣时显式报错，不静默降级。

## 十一、待确认问题

1. 未登录用户查看商户列表时，展示“登录后查看会员优惠”。
2. admin 必须为所有启用用户等级配置会员消费折扣；缺少任一启用等级配置时不允许保存或启用。
3. 老的商户端折扣配置数据不迁移，由 admin 重新配置。
