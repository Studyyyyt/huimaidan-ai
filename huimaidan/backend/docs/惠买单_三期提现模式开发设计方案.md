# 惠买单第三期开发设计方案：提现模式

更新时间：2026-06-05

## 一、文档目的

本文档用于确认惠买单第三期“提现模式”的后端设计方案。

本期目标是在当前一期、二期已完成的惠买单能力基础上，新增商户长期合作模式中的“提现模式”，并明确以下约束：

- 商户合作模式由平台按商户长期二选一配置。
- 当前项目整体就是基于 CRMEB 开发的惠买单，不拆分商城与惠买单为两套独立系统。
- 提现模式复用 CRMEB 现有商户余额、提现申请、平台审核、打款凭证上传能力。
- 禁止静默降级、禁止 mock 数据、禁止隐藏错误。

本文档确认后，再进入详细 SQL、接口开发和联调阶段。

---

## 二、现状基线

### 2.1 当前已完成能力

当前仓库已具备以下惠买单基础能力：

- 垫资池模式订单闭环已完成。
- 用户端到店买单、支付、支付回调已完成。
- 支付成功后当前只支持按垫资池模式扣减池余额。
- 商户端已具备惠买单订单、统计、垫资池查询能力。
- 平台端已具备惠买单订单统计、差价统计、垫资池管理能力。

当前仓库也已具备 CRMEB 原生商户财务能力：

- 商户可配置收款方式。
- 商户可提交提现申请。
- 平台可审核提现申请。
- 平台可上传打款凭证。
- 审核驳回后可回退商户余额。

### 2.2 当前代码入口

本期设计直接围绕以下现有代码改造：

- `app/common/repositories/huimaidan/OrderRepository.php`
- `app/common/repositories/huimaidan/SettlementRepository.php`
- `app/common/repositories/huimaidan/DiscountRuleRepository.php`
- `app/common/repositories/system/financial/FinancialRepository.php`
- `app/controller/merchant/system/financial/Financial.php`
- `app/controller/admin/system/financial/Financial.php`
- `route/merchant/huimaidan.php`
- `route/admin/huimaidan.php`
- `route/merchant/accounts.php`
- `route/admin/accounts.php`

### 2.3 当前问题

二期明确只支持垫资池模式，未实现提现模式，因此目前存在以下缺口：

- 商户没有“合作模式”字段，无法区分垫资池模式和提现模式。
- 惠买单支付回调没有提现模式分支。
- 提现模式商户仍被强制要求绑定垫资池。
- 提现申请虽然已有原生链路，但没有惠买单业务来源、手续费、二维码类型统计口径。
- 平台无法从惠买单维度查看提现模式的申请、审核、手续费和打款结果。

## 三、第三期最终设计结论

### 3.1 商户合作模式

平台为每个商户长期配置一种合作模式，二选一：

- `1`：垫资池模式
- `2`：提现模式

本期按“长期固定模式”设计，不支持同一商户在历史订单未清算完毕时自动切换模式，不做中途切换兼容。

### 3.2 提现模式资金承载方式

提现模式不新增独立结算账户表，直接复用 CRMEB 商户现有余额字段 `merchant.mer_money` 承载可提现余额。

但是必须补充业务标记，确保平台能明确识别：

- 哪些余额来自惠买单订单入账
- 哪些提现申请属于惠买单提现
- 每笔提现的手续费率、手续费金额和实际打款金额

### 3.3 提现模式手续费口径

手续费按商户单独配置费率。

资金规则如下：

- 用户支付成功时，商户余额按用户实付全额入账。
- 提现申请提交时，再按申请金额计算手续费。
- 实际打款金额 = 提现金额 - 手续费金额。

本期不在订单支付时预扣手续费。

### 3.4 收款方式

提现模式下仅允许两种收款方式：

- 微信收款码
- 支付宝收款码

不支持银行卡提现。

每个商户上传并维护当前使用的收款二维码，平台审核和打款时按二维码类型统计。

### 3.5 提现申请并发规则

同一个提现模式商户任意时刻只允许存在一笔未完结提现申请。

未完结范围包括：

- 待审核
- 审核通过待打款
- 已审核但未上传打款凭证

如存在未完结申请，商户再次提交时必须显式报错，不允许静默覆盖或排队创建。

## 四、本期范围与非范围

### 4.1 本期范围

- 新增商户合作模式字段。
- 新增商户提现模式手续费配置字段。
- 改造惠买单支付回调，支持提现模式余额入账。
- 改造惠买单优惠规则配置，提现模式不强制绑定垫资池。
- 复用 CRMEB 商户财务链路，实现惠买单提现申请、平台审核、凭证回填。
- 为提现申请补充惠买单业务来源、手续费、二维码类型统计字段。
- 新增惠买单商户端提现概览与申请查询接口。
- 新增惠买单平台端提现审核与统计接口。

### 4.2 本期明确不做

- 不拆分出独立的惠买单钱包系统。
- 不开发自动微信企业付款或自动支付宝转账。
- 不开发多笔并行提现。
- 不开发商户模式自动切换。
- 不做银行卡提现。
- 不改变 CRMEB 原厂用户佣金提现逻辑。

## 五、数据模型设计

### 5.1 商户表扩展

建议扩展 `eb_merchant`：

```sql
ALTER TABLE `eb_merchant`
ADD COLUMN `huimaidan_settlement_mode` tinyint(1) NOT NULL DEFAULT '1' COMMENT '惠买单合作模式 1垫资池 2提现模式',
ADD COLUMN `huimaidan_withdraw_rate` decimal(5,2) NOT NULL DEFAULT '0.00' COMMENT '惠买单提现手续费率(%)';
```

字段说明：

- `huimaidan_settlement_mode`
  - 平台唯一配置入口
  - 商户端只读
  - 为兼容当前已上线的一期、二期商户，数据库迁移时历史惠买单商户默认回填为 `1=垫资池模式`
- `huimaidan_withdraw_rate`
  - 仅提现模式有效
  - 例如 `2.50` 表示提现手续费率为 `2.50%`

### 5.2 惠买单订单表扩展

建议扩展 `eb_store_order`：

```sql
ALTER TABLE `eb_store_order`
ADD COLUMN `settlement_mode` tinyint(1) NOT NULL DEFAULT '1' COMMENT '惠买单结算模式 1垫资池 2提现模式',
ADD COLUMN `huimaidan_income_status` tinyint(1) NOT NULL DEFAULT '0' COMMENT '惠买单入账状态 0未入账 1已入账';
```

说明：

- `settlement_mode`
  - 订单创建时按商户配置快照保存
  - 防止后续平台修改商户合作模式时影响历史订单处理
- `huimaidan_income_status`
  - 仅提现模式使用
  - 用于标记这笔订单是否已成功计入商户余额
  - 支付重复回调时作为幂等辅助字段

### 5.3 商户提现申请表扩展

本期复用 CRMEB 原生 `eb_financial`，建议扩展以下字段：

```sql
ALTER TABLE `eb_financial`
ADD COLUMN `business_type` varchar(32) NOT NULL DEFAULT '' COMMENT '业务来源，如huimaidan',
ADD COLUMN `fee_rate` decimal(5,2) NOT NULL DEFAULT '0.00' COMMENT '手续费率(%)',
ADD COLUMN `fee_amount` decimal(12,2) NOT NULL DEFAULT '0.00' COMMENT '手续费金额',
ADD COLUMN `real_transfer_amount` decimal(12,2) NOT NULL DEFAULT '0.00' COMMENT '实际打款金额',
ADD COLUMN `account_type` tinyint(1) NOT NULL DEFAULT '0' COMMENT '收款码类型 2微信 3支付宝',
ADD COLUMN `trade_channel` varchar(32) NOT NULL DEFAULT '' COMMENT '交易渠道，如huimaidan_withdraw',
ADD COLUMN `audit_remark` varchar(255) NOT NULL DEFAULT '' COMMENT '审核备注';
```

字段用途：

- `business_type`
  - 标记申请是否属于惠买单
  - 本期固定写 `huimaidan`
- `fee_rate`
  - 提现申请创建时按商户费率快照保存
- `fee_amount`
  - `extract_money * fee_rate / 100`
- `real_transfer_amount`
  - `extract_money - fee_amount`
- `account_type`
  - 平台统计微信提现和支付宝提现时直接使用
- `trade_channel`
  - 便于后续按业务来源分组统计

### 5.4 商户账单/流水记录

本期不新建独立结算表，但必须复用现有商户账单或资金流水能力，增加惠买单专用业务类型。

建议新增至少两类账单类型：

- `huimaidan_order_income`：惠买单订单入账
- `huimaidan_withdraw_fee`：惠买单提现手续费

这样即使不拆账户，也能保证后续按业务来源追溯。

## 六、核心业务流程设计

### 6.1 平台配置商户合作模式

流程：

1. 平台进入商户管理或惠买单商户配置页。
2. 选择商户合作模式：
   - 垫资池模式
   - 提现模式
3. 若选择提现模式：
   - 必须填写提现手续费率
4. 保存后：
   - 商户优惠规则配置逻辑随模式切换
   - 支付回调按模式进入不同分支

约束：

- 未纳入惠买单的商户不得开通惠买单支付。
- 历史已运行商户在数据库迁移后默认视为垫资池模式，后续由平台按商户调整。
- 提现模式费率小于 `0` 或大于 `100` 必须报错。
- 历史订单不回写、不重算。

### 6.2 提现模式下的优惠规则配置

当前 `DiscountRuleRepository` 在新增、编辑、启用规则时强制绑定已启用垫资池。

本期改造为：

- 垫资池模式：
  - 维持当前逻辑
  - 必须绑定已启用垫资池
- 提现模式：
  - 不强制绑定垫资池
  - `pool_id` 允许为空

错误处理要求：

- 若商户是垫资池模式但未绑定池子，显式返回错误。
- 若商户是提现模式却错误传入禁用池子，不自动忽略，按参数错误返回。

### 6.3 用户支付成功后的入账分支

#### 6.3.1 垫资池模式

维持现有逻辑：

- 记录订单
- 扣减垫资池
- 写池流水
- 计算平台差价

#### 6.3.2 提现模式

新增逻辑：

1. 支付回调读取订单快照中的 `settlement_mode=2`
2. 不扣减垫资池
3. 将 `pay_price` 全额增加到商户 `mer_money`
4. 写入商户账单，类型为 `huimaidan_order_income`
5. 更新订单：
   - `huimaidan_income_status = 1`
   - `platform_profit = 0.00`
6. 记录支付成功日志

关键约束：

- 订单支付回调必须幂等。
- 同一订单重复回调时，不允许重复加商户余额。
- 入账失败必须整笔事务回滚，不允许订单显示已支付但余额未到账。

### 6.4 商户收款码配置流程

提现模式商户首次申请提现前，必须先配置收款方式。

规则：

- 只允许微信收款码或支付宝收款码
- 必须上传二维码图片
- 必须填写收款人姓名
- 微信码需填写微信号
- 支付宝码需填写支付宝账号

本期建议：

- 复用 `FinancialRepository::saveAccount`
- 但新增惠买单场景校验，禁止选择银行卡 `financial_type=1`

### 6.5 商户提现申请流程

流程：

1. 商户进入惠买单结算页查看：
   - 当前可提现余额
   - 当前手续费率
   - 当前收款码类型
   - 当前是否存在未完结申请
2. 商户输入申请金额
3. 系统校验：
   - 商户当前模式必须为提现模式
   - 必须已配置微信码或支付宝码
   - 金额必须大于等于 `500`
   - 金额不得大于当前可提现余额
   - 当前不得存在未完结申请
4. 系统计算：
   - 手续费金额
   - 实际打款金额
5. 创建提现申请
6. 同时扣减 `mer_money`
7. 返回申请成功

计算公式：

```text
fee_amount = round(extract_money * fee_rate / 100, 2)
real_transfer_amount = extract_money - fee_amount
```

说明：

- 商户申请金额是“要从余额里提走的金额”
- 平台实际线下扫码支付的是 `real_transfer_amount`
- 手续费差额留在平台侧作为收益

### 6.6 平台审核与打款流程

本期复用 CRMEB 财务申请状态结构：

- `status`
  - `0`：待审核
  - `1`：审核通过
  - `-1`：审核拒绝
- `financial_status`
  - `0`：未打款
  - `1`：已打款

流程：

1. 平台查看待审核列表
2. 审核时展示：
   - 商户名称
   - 申请金额
   - 手续费率
   - 手续费金额
   - 实际打款金额
   - 收款码类型
   - 收款二维码图片
3. 审核通过：
   - `status = 1`
   - `financial_status = 0`
4. 管理员线下扫码付款
5. 上传打款凭证
6. 完成打款：
   - `financial_status = 1`
   - 记录打款时间、操作人、凭证图

### 6.7 审核驳回流程

若审核拒绝：

1. `status = -1`
2. 填写拒绝原因
3. 将原申请金额全额退回 `mer_money`
4. 写回退账单

注意：

- 驳回时回退的是申请金额 `extract_money`
- 不是 `real_transfer_amount`
- 因为手续费只在成功提现时才成立

### 6.8 未完结申请限制规则

商户提交提现申请前，检查：

```text
business_type = 'huimaidan'
AND mer_id = 当前商户
AND is_del = 0
AND (
    status = 0
    OR (status = 1 AND financial_status = 0)
)
```

命中即返回错误：

`当前存在未完成提现申请，请等待平台处理后再申请`

## 七、状态机设计

### 7.1 商户合作模式状态

```text
平台未配置
  ├── 垫资池模式
  └── 提现模式
```

### 7.2 提现申请状态机

```text
商户提交申请
  -> 待审核(status=0, financial_status=0)
    -> 审核拒绝(status=-1, financial_status=0)
    -> 审核通过(status=1, financial_status=0)
      -> 上传打款凭证(status=1, financial_status=1)
```

### 7.3 订单入账状态机

```text
待支付
  -> 已支付未入账(仅事务处理中短暂存在)
    -> 已支付已入账(huimaidan_income_status=1)
```

原则：

- 不允许出现“订单已支付但商户余额未入账”的持久化中间态。
- 若入账失败，整个支付成功事务必须回滚。

## 九、统计口径设计

### 9.1 垫资池模式统计

仍沿用当前统计口径：

- `platform_profit` 代表差价收入

### 9.2 提现模式统计

提现模式下，不再以订单的 `platform_profit` 统计平台收益。

平台收益口径改为：

- 已完成提现申请的 `fee_amount` 累计值

建议新增以下统计项：

- 提现模式订单入账总额
- 当前商户可提现余额
- 待审核提现金额
- 待打款提现金额
- 已完成提现金额
- 已完成提现手续费总额
- 微信收款码提现笔数与金额
- 支付宝收款码提现笔数与金额

### 9.3 混合统计原则

平台端惠买单统计页面需区分两类模式：

- 垫资池模式：看差价
- 提现模式：看手续费

不允许把差价收入和提现手续费混成同一字段静默返回。

## 十一、验证规则

### 11.1 商户模式配置

- 合作模式必须为 `1` 或 `2`
- 提现模式费率必须大于等于 `0` 且小于等于 `100`

### 11.2 收款码配置

- 仅允许微信和支付宝
- 二维码图片必传
- 微信码必须填写微信号
- 支付宝码必须填写支付宝账号

### 11.3 提现申请

- 商户必须处于提现模式
- 必须已配置收款码
- 最低提现金额 `500`
- 提现金额不得大于 `mer_money`
- 只允许一笔未完结申请

### 11.4 平台审核

- 拒绝必须填写原因
- 完成打款必须上传凭证
- 非惠买单申请不得走惠买单审核接口

## 十二、错误处理原则

本期严格遵守 Debug-First：

- 不允许提现模式商户在支付回调中静默降级为垫资池模式
- 不允许未配置模式的商户继续支付
- 不允许未配置收款码的商户继续提现
- 不允许忽略重复申请
- 不允许忽略手续费计算失败
- 不允许忽略余额回退失败

所有失败必须显式返回业务错误，并记录日志。

## 十四、验收标准

### 14.1 交易链路

- 提现模式商户支付成功后，商户余额按用户实付全额增加
- 同一订单重复回调不重复入账
- 提现模式订单不触发垫资池扣减

### 14.2 提现链路

- 商户仅能选择微信码或支付宝码
- 商户可看到手续费和实际到账金额
- 商户存在未完结申请时不能再次提交
- 平台可审核通过、驳回并回退余额
- 平台可上传打款凭证并完成状态流转

### 14.3 统计链路

- 平台可区分垫资池模式差价统计和提现模式手续费统计
- 可区分微信提现与支付宝提现数据
- 所有金额统计来源于真实订单、余额和提现申请数据

### 14.4 工程验证

- 所有新增和修改 PHP 文件通过 `php -l`
- 若新增类或命名空间，执行 `composer dump-autoload`
- 路由、权限、前端对接文档同步更新
- 涉及队列、缓存或常驻进程时，交付中明确重启要求
