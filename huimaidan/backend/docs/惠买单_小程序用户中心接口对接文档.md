# 惠买单小程序用户中心接口对接文档

更新时间：2026-06-11

## 1. 对接范围

本文档对应第 3 批：用户中心聚合、积分、浏览记录、收藏、优惠券配套能力。

本批新增用户资产聚合接口，其余用户中心页面优先复用 CRMEB 已有移动端接口。所有接口均使用真实用户数据，不提供 mock 数据。

## 2. Token 请求头

用户端登录接口返回的 token 后续统一放到请求头：

```text
Authorization: Bearer {token}
```

后端兼容读取以下请求头，优先级从高到低：

| 请求头 | 示例 | 说明 |
| --- | --- | --- |
| `X-Token` | `X-Token: {token}` | CRMEB 原有移动端 token 头，继续兼容。 |
| `Authorization` | `Authorization: Bearer {token}` | 小程序推荐格式。 |
| `Authori-zation` | `Authori-zation: Bearer {token}` | 兼容部分历史客户端写法。 |

注意：

- `Authorization: Bearer {token}` 中 `Bearer` 后必须带真实 token。
- 后端会去掉 `Bearer` 前缀后再校验 token。
- Token 仍需存在于后端缓存 `user_{token}` 中；若缓存过期，会返回“token 已过期，请重新登录”。

## 3. 用户资产聚合

```text
GET /api/huimaidan/user/assets
```

登录态：需要用户 Token。

请求参数：无。

响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "commission": "12.50",
    "points": 168,
    "couponCount": 3,
    "vipLevel": 2
  }
}
```

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `code` | number | 固定值 | 成功为 `0`。 |
| `msg` | string | 固定值 | 成功为 `success`。 |
| `data.commission` | string | `user.brokerage_price` | 当前可用佣金余额。 |
| `data.points` | number | `user.integral` | 当前可用积分。 |
| `data.couponCount` | number | `user.total_coupon` | 当前所有可用优惠券数量，不限于惠买单专属券。 |
| `data.vipLevel` | number | `user.member_level` | 会员等级。 |

失败说明：

- 用户不存在：接口显式返回“用户不存在”。
- Token 无效或未登录：走现有登录中间件错误。

## 4. 用户权益摘要

```text
GET /api/huimaidan/user/benefit
```

登录态：需要用户 Token。

用于“我的”页面展示惠买单专属权益摘要。

主要字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `can_use` | boolean | 当前用户是否可使用惠买单。 |
| `benefit_text` | string | 权益展示文案。 |
| `order_count` | number | 已支付惠买单订单数。 |
| `pay_amount` | string | 已支付惠买单实付金额合计。 |
| `saved_amount` | string | 已支付惠买单优惠金额合计。 |

## 5. 积分接口

积分能力直接复用 CRMEB 已有接口：

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 积分概览 | `GET /api/user/integral/info` | 返回当前积分、冻结积分、累计获取等。 |
| 积分明细 | `GET /api/user/integral/lst` | 支持 `page`、`limit` 分页。 |

如果系统未开启积分功能，接口会显式返回“积分功能未开启”。

## 6. 收藏接口

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 收藏列表 | `GET /api/user/relation/merchant/lst` | 商户收藏列表。 |
| 收藏商户 | `POST /api/user/relation/create` | 固定传 `type=10`。 |
| 取消收藏 | `POST /api/user/relation/delete` | 固定传 `type=10`。 |
| 收藏状态 | `GET /api/user/relation/check/:id` | `:id` 为商户 ID，返回 `isCollected`。 |

收藏状态响应：

```json
{
  "isCollected": true
}
```

## 7. 店铺浏览历史接口

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 自动写入浏览记录 | `GET /api/huimaidan/store/detail/:id` | 登录用户访问店铺详情成功后，后端自动写入。未登录不写入。 |
| 店铺浏览历史列表 | `GET /api/huimaidan/user/merchant_history` | 返回当前用户最近浏览店铺卡片，支持分页和经纬度距离。 |
| 删除单条店铺浏览历史 | `POST /api/huimaidan/user/merchant_history/delete/:id` | `:id` 为 `history_id`，只允许删除本人记录。 |
| 批量删除或清空 | `POST /api/huimaidan/user/merchant_history/batch_delete` | `history_ids` 批量删除，或 `clear=1` 清空本人记录。 |

浏览记录范围：只记录商户详情页，不记录首页、列表、支付页、订单页等其他惠买单页面。

旧接口边界：

| 接口 | 用途 |
| --- | --- |
| `GET /api/user/history` | CRMEB 商品/SPU 浏览历史，不用于惠买单店铺历史。 |
| `POST /api/common/visit` | 页面 PV 或页面访问记录，不用于惠买单店铺历史列表。 |

详细字段、错误文案和前端封装见 `docs/惠买单_店铺浏览历史前后端对接文档_2026-06-18.md`。

## 8. 优惠券接口

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 可领券列表 | `GET /api/coupon/list`、`GET /api/coupon/store/:id` | 复用现有领券接口。 |
| 领取优惠券 | `POST /api/coupon/receive/:id` | 复用现有领取接口。 |
| 下单可用券 | `GET /api/coupon/usable` | 查询可用于惠买单展示和支付型下单抵扣的券；前端下单时使用返回的 `id` 作为 `couponId`。 |

## 9. 前端调用建议

```ts
export const huimaidanUserApi = {
  assets: () => request.get('/huimaidan/user/assets'),
  benefit: () => request.get('/huimaidan/user/benefit'),
  integralInfo: () => request.get('/user/integral/info'),
  integralList: (params: { page?: number; limit?: number }) =>
    request.get('/user/integral/lst', params),
  collectionList: (params: { page?: number; limit?: number }) =>
    request.get('/user/relation/merchant/lst', params),
  checkCollection: (shopId: number) =>
    request.get(`/user/relation/check/${shopId}`),
  shopHistory: (params: { page?: number; limit?: number; latitude?: number; longitude?: number }) =>
    request.get('/huimaidan/user/merchant_history', params),
}
```

## 10. 数据和部署说明

- 本批新增 SQL：`docs/sql/惠买单_店铺浏览历史表.sql`。
- 用户资产聚合依赖现有 `user` 表、优惠券用户表和 CRMEB 用户模型访问器。
- 涉及 PHP 路由与长驻进程环境，部署后需要清理路由/应用缓存；如生产使用 Swoole，需要重启 Swoole。
