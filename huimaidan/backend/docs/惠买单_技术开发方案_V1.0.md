## 一、项目概述

### 1.1 产品定位

惠买单是一个本地生活优惠平台，核心模式为：**平台采购商家折扣权 → 加价开放给用户 → 赚取差价**。用户通过小程序到店消费，扫码输入金额后自动享受平台折扣价，完成支付。

### 1.2 核心业务模型

```
平台与商家谈底价折扣（如 5 折）
    → 平台为商家垫资充值（如 5000 元）建立垫资池
    → 平台加价给用户（如 6 折）
    → 用户支付 6 折价
    → 平台按 5 折底价从垫资池扣减
    → 平台赚取 1 折差价
    → 垫资池余额不足时，平台为商家再次充值（循环）
```

### 1.3 两种商家合作模式

| 维度 | 垫资池模式 | 提现模式 |
|------|-----------|---------|
| 充值主体 | **平台**向商家垫资充值（如 5000 元） | 无需充值 |
| 用户支付价 | 平台折扣价 | 平台折扣价 |
| 池子扣减 | 按商家底价实时扣减 | 不涉及 |
| 平台收入 | 差价（用户价 - 商家底价） | 手续费（按比例抽成） |
| 商家回收成本 | 垫资池消耗完毕后，**平台**再次充值（循环），商家无需主动充值 | 商家手动申请提现（最低 500 元） |
| 余额不足处理 | 允许继续支付并扣减到负数，平台需及时补充分配 | 不适用 |
| 余额预警 | 低于阈值自动通知平台管理员 | 不适用 |

### 1.4 关键设计决策汇总

| 编号 | 决策项 | 结论 |
|------|--------|------|
| D-01 | 优惠类型 | **折扣 + 优惠券 + 积分**，三种全上 |
| D-02 | 优惠叠加规则 | 取最优（自动选择优惠力度最大的） |
| D-03 | 会员体系 | 复用 CRMEB 现有会员/分销等级能力，普通会员注册即发放，VIP 通过拉人和消费两类规则开通；具体条件和 VIP 提成比例由平台端配置；普通会员默认提成 0.00% |
| D-04 | 垫资池扣减时机 | 支付成功时实时扣减 |
| D-05 | 垫资池不足处理 | **余额不足时仍允许支付，订单扣减可透支为负数** |
| D-06 | 垫资池预警 | **设置余额预警阈值，低于阈值时自动通知平台和商家** |
| D-07 | 商家结算方式 | 按折扣价结算充值 |
| D-08 | 提现规则 | 手动申请，最低 500 元 |
| D-09 | 区域层级 | 仅城市一级 |
| D-10 | 用户评价 | MVP 不展示 |
| D-11 | 第三方服务 | 短信/地图/OSS，CRMEB 内置 |

```
│ 订单完成  │◀───│ 差价入账  │◀───│ 池子扣减  │◀───│ 支付成功  │◀───│ 微信支付  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

**详细步骤**：

1. 用户扫描商家桌台二维码，进入该商家的买单页
2. 页面展示商家名称、可用优惠标签（如「惠买单 6 折」）
3. 用户输入本次消费金额（如 300 元）
4. 系统调用优惠引擎，计算最优优惠：
   - 遍历该商家所有生效的优惠规则（折扣/立减/满减）
   - 分别计算每种规则下的实付金额
   - 取实付金额最小的规则作为最优优惠
5. 展示优惠明细：原价 300 → 6 折 → 实付 180
6. 用户确认，发起微信支付
7. 支付成功回调：
   - 写入订单（含优惠快照、商家底价 150、平台差价 30）
   - 垫资池扣减 150（按商家底价）
   - 记录池流水
   - 差价 30 入平台收入
8. 返回支付成功页，展示订单详情

### 5.2 垫资池余额不足处理流程

```
用户确认支付 → 校验垫资池已启用
                    │
                    ├── 已启用
                    │       └── 按本次需扣减金额直接扣减 → 支付成功
                    │               └── 余额不足时允许扣减后变为负数
                    │
                    └── 未启用 / 未绑定
                            └── 拒绝支付
                                └── 提示「该商家优惠暂不可用，请联系商家」
```

**垫资池预警机制**：

```
每次扣减后检查余额 → 余额 ≤ 预警阈值？
                          │
                          ├── 是 → 触发预警
                          │       ├── 平台端：后台预警面板标红
                          │       ├── 商家端：消息通知「池余额不足，请尽快充值」
                          │       └── 记录预警日志
                          │
                          └── 否 → 正常
```

预警阈值由平台在后台为每个商家单独配置（默认建议值：500 元或最近 7 天日均消耗 × 3）。

### 5.3 平台为商家垫资充值流程

```
平台监控垫资池余额 → 余额低于预警阈值
    → 平台管理员发起垫资充值（如 5000 元）
    → 系统记录充值流水，池余额增加
    → 商家端显示余额已补充
    → 平台内部记账（垫资成本）
```

### 5.4 提现模式商家结算流程（需平台审核）

```
用户支付成功 → 订单金额入商家待结算账户
    → 商家在后台查看可提现余额
    → 商家发起提现申请（≥ 500 元）
    → **平台审核**（审核通过/驳回）
    → 审核通过 → 线下打款
    → 平台标记已发放 → 完成
    → 审核驳回 → 退回商家账户，备注驳回原因
```

### 5.5 订单状态流转

```
待支付 ──▶ 支付中 ──▶ 支付成功 ──▶ 已完成
  │                      │
  │                      ├──▶ 退款中 ──▶ 已退款
  │                      │
  └──▶ 已取消             └──▶ 异常
```

## 七、优惠计算引擎设计

### 7.1 计算规则

```
输入：商家ID、消费金额
输出：最优优惠方案

算法：
1. 查询该商家所有生效的优惠规则
2. 对每条规则计算实付金额：
   - 折扣：实付 = 消费金额 × 平台折扣率
   - 优惠券：实付 = max(消费金额 - 券面额, 0.01)
   - 积分：实付 = 消费金额 - 积分抵扣金额（积分兑换比例可配）
3. 取实付金额最小的规则
4. 计算商家底价 = 消费金额 × 商家底价折扣率
5. 计算平台差价 = 实付 - 商家底价
6. 返回最优方案
```

### 7.2 关键约束

- 实付金额最低 0.01 元
- 保留两位小数（四舍五入）
- 订单创建时写入优惠快照（JSON），历史订单不受后续规则变更影响
- 垫资池模式商家才计算差价；提现模式商家差价 = 0

## 八、安全与风控

### 8.1 数据隔离

| 角色 | 数据权限 |
|------|---------|
| 平台管理员 | 全部数据 |
| 区域运营 | 仅授权城市数据 |
| 商家 | 仅本商家/本门店数据 |
| 用户 | 仅本人数据 |

### 8.2 关键操作留痕

所有涉及金额变更的操作必须记录操作日志：
- 操作人 ID
- 操作时间
- 操作类型
- 变更前值 / 变更后值
- 关联订单号
- 备注

### 8.3 并发控制

- 垫资池扣减使用 Redis 分布式锁，防止并发超扣
- 订单支付回调做幂等处理（基于订单号去重）
- 垫资池状态校验与扣减必须在同一事务中，避免启停状态变化造成脏写

### 9.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 微信支付审核延迟 | 上线延期 | 提前提交审核材料，准备备用支付方案 |

| CRMEB 版本升级冲突 | 二开代码失效 | 独立模块目录，最小化侵入，做好版本管理 |
