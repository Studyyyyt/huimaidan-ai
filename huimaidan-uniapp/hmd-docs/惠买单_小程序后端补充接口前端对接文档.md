# 惠买单小程序后端补充接口前端对接文档

更新时间：2026-06-12

## 1. 本轮说明

本轮按方案 A 做后端增量适配：复用现有 CRMEB 与惠买单接口体系，不新建一套小程序 BFF。

本轮已确认：

- 保留现有 `/api/huimaidan/order/create` 创建订单后发起后端支付的行为。
- 暂不做微信、支付宝等第三方支付联调。
- 跳过 `POST /home/aiSearch`。
- 不使用 mock 数据，不静默降级，不隐藏错误。
- 本轮不需要建表或扩展表，无必须执行 SQL。

## 2. 新增接口总览

| 前端需求 | 后端接口 | 登录态 | 说明 |
| --- | --- | --- | --- |
| 筛选条件 | `GET /api/huimaidan/store/filters` | 否 | 分类、城市、距离、排序配置 |
| 订单统计 | `GET /api/huimaidan/order/statistics` | 是 | 我的买单状态数量 |
| 支付结果 | `GET /api/huimaidan/order/pay_result/:id` | 是 | 只读查询，不触发支付 |
| 下单可用券 | `GET /api/coupon/usable` | 是 | 查询当前用户可用于商户买单的券 |
| 收藏状态 | `GET /api/user/relation/check/:id` | 是 | 查询商户是否已收藏 |

## 3. 筛选条件

`GET /api/huimaidan/store/filters`

登录态：不需要。

返回字段：

| 字段 | 说明 |
| --- | --- |
| `key=distance` | 固定距离筛选：1km、3km、5km、10km |
| `key=category` | 当前存在有效惠买单商户的真实分类 |
| `key=city` | 当前存在有效惠买单商户的真实城市 |
| `key=sort` | 后端真实支持的排序：`default`、`location` |

说明：

- 后端不返回评分、销量排序，因为当前商户发现查询未实现真实评分/销量排序。
- 商户列表已支持 `distance` 参数；传 `distance` 时必须同时传 `latitude` 和 `longitude`。

商户列表筛选参数映射：

| 小程序字段 | 后端字段 | 说明 |
| --- | --- | --- |
| `categoryId` | `category_id` | 分类 ID |
| `keyword` | `keyword` | 搜索词 |
| `longitude` | `longitude` | 经度 |
| `latitude` | `latitude` | 纬度 |
| `distance` | `distance` | 距离范围，单位 km |
| `sortBy=distance` | `order=location` | 距离排序 |
| `pageSize` | `limit` | 每页数量 |

## 4. 订单统计

`GET /api/huimaidan/order/statistics`

登录态：需要用户 Token。

返回：

```json
{
  "unpaid": 0,
  "completed": 5,
  "refund": 0
}
```

统计口径：

- `unpaid`：当前用户未支付惠买单订单。
- `completed`：当前用户已支付且完成的惠买单订单。
- `refund`：当前用户惠买单订单关联的退款/售后单数量。

## 5. 支付结果

`GET /api/huimaidan/order/pay_result/:id`

登录态：需要用户 Token。

`:id` 支持：

- `store_order.order_id`
- `store_group_order.group_order_id`

返回：

```json
{
  "paid": true,
  "orderId": 123456,
  "storeOrderId": 789,
  "payTime": "2026-06-01 12:30:00"
}
```

说明：

- 该接口只查询本地订单支付状态。
- 不调用微信或支付宝查询接口。
- 查询其他用户订单会返回“订单不存在”。

## 6. 下单可用券

`GET /api/coupon/usable`

登录态：需要用户 Token。

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `shopId` 或 `mer_id` | int | 是 | 商户 ID |
| `amount` | decimal | 是 | 订单金额 |
| `page` | int | 否 | 页码 |
| `limit` | int | 否 | 每页数量 |

返回：

```json
{
  "count": 1,
  "total": 1,
  "list": [
    {
      "id": 101,
      "couponId": 201,
      "name": "满100减10",
      "amount": "10.00",
      "threshold": "100.00",
      "condition": "满100.00元可用",
      "expireTime": "2026-07-01 00:00:00",
      "usedTime": "",
      "status": "unused"
    }
  ]
}
```

可用口径：

- 当前用户已领取。
- 未使用、未过期、未失效。
- 满足金额门槛。
- 当前商户店铺券可用。
- 平台通用券可用。
- 平台跨店券必须包含当前商户。
- 商品券、品类券在惠买单到店买单无商品上下文时不返回。

重要限制：

- 本接口只查询可展示/可选择的 CRMEB 用户券。
- 第 4 批起，支付型惠买单下单接口可使用返回的 `id` 作为 `couponId`。

## 7. 收藏状态

`GET /api/user/relation/check/:id`

登录态：需要用户 Token。

`:id` 为商户 ID。

返回：

```json
{
  "isCollected": true
}
```

收藏/取消收藏继续复用原接口：

| 操作 | 接口 |
| --- | --- |
| 添加收藏 | `POST /api/user/relation/create`，参数 `{ "type_id": shopId, "type": 10 }` |
| 取消收藏 | `POST /api/user/relation/delete`，参数 `{ "type_id": shopId, "type": 10 }` |
| 收藏列表 | `GET /api/user/relation/merchant/lst` |

## 8. 下单接口未支持字段

`POST /api/huimaidan/order/create`

当前支持字段为：

| 字段 | 说明 |
| --- | --- |
| `mer_id` | 商户 ID |
| `amount` | 消费金额 |
| `pay_type` | 支付方式 |
| `couponId` / `coupon_id` | 用户券 ID |
| `usePoints` / `use_points` | 是否使用积分 |
| `useMemberDiscount` / `use_member_discount` | 是否参与会员折扣 |
| `mark` | 备注 |
| `return_url` | 支付宝返回地址 |

以下小程序字段本轮不支持，后端收到会显式失败，不再静默忽略：

- `pointsAmount`
- `points_amount`
- `discountType`
- `discount_type`

错误示例：

```json
{
  "message": "惠买单订单暂未支持以下抵扣参数：pointsAmount、discountType"
}
```

## 9. 本轮跳过项

### AI 搜索

`POST /home/aiSearch` 本轮跳过。原因：

- 没有真实 AI 服务配置。
- 没有模型、提示词、预算、失败策略。
- 小程序开发文档将 AI 搜索列为 P2，不阻塞主流程。

### 第三方支付联调

本轮不做微信、支付宝真实联调。现有后端支付入口保留，新增的支付结果接口仅查询本地订单状态。

### SQL

本轮无需建表或扩展表，因此没有必须执行的 SQL 脚本。

## 10. 前端建议封装

```typescript
export const huimaidanApi = {
  filters: () => request.get('/huimaidan/store/filters'),
  orderStatistics: () => request.get('/huimaidan/order/statistics'),
  payResult: (id: number) => request.get(`/huimaidan/order/pay_result/${id}`),
  usableCoupons: (params: { shopId: number; amount: number; page?: number; limit?: number }) =>
    request.get('/coupon/usable', params),
  checkCollection: (shopId: number) => request.get(`/user/relation/check/${shopId}`),
}
```
